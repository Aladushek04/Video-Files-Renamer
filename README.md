# Video Files Renamer

Локальный инструмент для переименования видео по метаданным **StashDB**,
**FansDB** и **ThePornDB**.

Он находит сцену по отпечатку файла (OSHASH), затем — по текстовому имени, и
только в последнюю очередь — эвристикой. Готовое предложение
выгружается в CSV, человек проверяет и правит его, и лишь потом файлы
переименовываются — с журналом и проверками «файл не менялся с момента
preview».

Наружу уходят только отпечатки файлов (OSHASH) и поисковые запросы по
очищенному остатку имени. Содержимое видео не читается целиком и наружу не
уходит; сами файлы остаются на месте.

---

## Что это

Проект — пакет `video_renamer` с CLI, TUI и скраперами:

| Путь | Назначение |
|---|---|
| `scripts\start.bat` | дружелюбный запуск: выбрать папку, preview, открыть CSV, apply |
| `scripts\start_tui.bat` | запуск Textual-интерфейса (сам создаёт `.venv` и ставит зависимости) |
| `video_renamer\cli.py` | `preview` (собрать предложения) и `apply` (применить одобренное) |
| `video_renamer\tui.py` | красивый TUI: таблица, фильтры, прогресс, подтверждение apply |
| `video_renamer\tui_model.py` | чистая модель фильтров/одобрений TUI без Textual |
| `video_renamer\merge_studios.py` | сливает несколько JSON-справочников в один |
| `video_renamer\scrapers\stashdb.py` | выгружает студии StashDB |
| `video_renamer\scrapers\fansdb.py` | выгружает студии FansDB |
| `video_renamer\scrapers\theporndb.py` | обогащает имена студиями ThePornDB через `findStudio` |
| `video_renamer\core\title_service.py` | сервисный слой без `print`/`argparse` |
| `video_renamer\core\title_matcher.py` | разбор имени, скоринг, сборка итогового имени |
| `video_renamer\core\title_cache.py` | локальный SQLite-кэш |
| `video_renamer\core\stashdb_client.py` | GraphQL-клиент stash-box с ретраями |
| `video_renamer\core\oshash.py` | точный OSHASH (совместим с `stashapp/stash`) |
| `video_renamer\core\clean_ph_names.py` | эвристика очистки имён — fallback |
| `data\studios.json` | объединённый справочник студий (355 559 ключей) |

Итоговое имя для найденной сцены собирается по шаблону:

```text
Студия - ДД.ММ.ГГГГ - Исполнитель 1, Исполнитель 2 - Название
```

Официальные строки StashDB не переделываются в Title Case: регистр
`title`, `studio.name` и имён исполнителей сохраняется как есть.

## Требования

- **Windows 10/11** (проверено на Windows 11). Пути, длины имён и
  санитизация заточены под Windows.
- **Python 3.10+** (проверено на 3.14). Ядро и CLI — только стандартная
  библиотека; TUI требует Textual.
- **Ключи API** — StashDB, FansDB и ThePornDB. Нужны только для сетевых
  запросов; без ключа StashDB `preview` работает офлайн.
- **pytest** — только для разработки (прогон тестов).

Ключи передаются через переменные окружения `STASHDB_API_KEY`,
`FANSDB_API_KEY`, `THE_PORNDB_API_KEY`. Если переменной нет, инструмент читает
`.env` в текущей папке. Значение из окружения имеет приоритет над `.env`.
Файл `.env` защищён от коммита; шаблон — `.env.example`.

### Как задать ключи

Текущая сессия PowerShell:

```powershell
$env:STASHDB_API_KEY = "ваш-ключ"
$env:FANSDB_API_KEY = "ваш-ключ"
$env:THE_PORNDB_API_KEY = "ваш-ключ"
```

Или скопируй `.env.example` в `.env` и заполни значения. Постоянно (для всех
новых окон терминала) можно использовать `[Environment]::SetEnvironmentVariable`;
после этого нужно открыть новый терминал.

## Быстрый старт

Самый простой путь — запустить `scripts\start.bat`, выбрать папку с видео и следовать
меню:

1. **Preview** — собрать предложения, ничего не переименовывая;
2. открыть `preview.csv`, проверить `approved` и `new`;
3. **Preview + применить после ревью** — применить только одобренное.

Для красивого интерактивного интерфейса запусти `scripts\start_tui.bat` — он сам
создаст `.venv`, поставит Textual и откроет TUI. Можно передать папку сразу:
`scripts\start_tui.bat D:\Videos\PH`.

### 1. Обновить справочник студий

Нужен один раз (и потом изредка): полный справочник студий заметно улучшает
распознавание имён в эвристике. В репозитории уже лежит объединённый
`data/studios.json` из StashDB, FansDB и ThePornDB (около 355 тысяч ключей).
Отдельные источники можно обновлять скраперами, а затем сливать:

```powershell
python -m video_renamer.scrapers.stashdb --apply
python -m video_renamer.scrapers.fansdb --apply
python -m video_renamer.scrapers.theporndb --apply
python -m video_renamer.merge_studios data/studios.json data/studios_fansdb.json data/studios_theporndb.json --out data/studios.json --apply
```

### 2. Собрать предложения по именам

```powershell
python -m video_renamer.cli preview D:\Videos\PH --csv preview.csv
```

Файлы на диске не меняются. Появляется `preview.csv` — одна строка на файл.

Первый раз удобно ограничить выборку:

```powershell
python -m video_renamer.cli preview D:\Videos\PH --limit 5 --csv preview.csv
```

### 3. Проверить CSV

Открыть `preview.csv` в Excel (файл уже в UTF-8 с BOM и с разделителем `;`).
Оставить `approved=y` только у строк, которые выглядят правильно; при
необходимости поправить `new` вручную.

### 4. Посмотреть план переименования

`apply` **по умолчанию** ничего не переименовывает — он только печатает план:

```powershell
python -m video_renamer.cli apply preview.csv --root D:\Videos\PH
```

### 5. Применить

```powershell
python -m video_renamer.cli apply preview.csv --root D:\Videos\PH --apply
```

Переименуются только строки с `approved=y`. В `rename_log.csv` попадает
журнал фактически выполненных переименований.

## Рабочий процесс: `preview` → ревью CSV → `apply`

### `preview`

```text
python -m video_renamer.cli preview <каталог> [--csv preview.csv] [--recursive]
                                 [--limit N] [--no-text] [--offline]
                                 [--refresh] [--studios data/studios.json]
                                 [--cache cache/title_fixer.sqlite3]
```

| Флаг | Что делает |
|---|---|
| `--csv PATH` | путь к CSV-ревью (по умолчанию `preview.csv`) |
| `--recursive` | обходить подпапки (по умолчанию — только верхний уровень) |
| `--limit N` | обработать только первые N файлов (порядок обхода детерминированный) |
| `--no-text` | отключить текстовый поиск в StashDB (быстрее, но меньше совпадений) |
| `--offline` | полностью без сети: только локальный кэш и эвристика |
| `--refresh` | игнорировать кэш и заново спросить StashDB |
| `--studios PATH` | справочник студий (по умолчанию `data/studios.json`) |
| `--cache PATH` | файл SQLite-кэша (по умолчанию `cache/title_fixer.sqlite3`) |

Порядок работы на каждый файл:

1. обход каталога → отбор видео по расширению;
2. размер файла + OSHASH (читаются только первые и последние 64 КиБ);
3. поиск сцены по OSHASH батчами (ответы берутся из кэша, если он есть);
4. если отпечаток ничего не дал — текстовый поиск по очищенному остатку имени;
5. если и это не дал уверенного совпадения — эвристика `clean_ph_names`.

`preview` **никогда** не переименовывает файлы.

### `apply`

```text
python -m video_renamer.cli apply <csv> --root <каталог> [--apply]
                                [--log rename_log.csv] [--force]
                                [--suffix-collisions]
```

| Флаг | Что делает |
|---|---|
| `--root PATH` | **обязателен**: каталог, относительно которого считаются `old`/`new` из CSV |
| `--apply` | реально переименовывать; без него — dry-run (печать плана) |
| `--log PATH` | журнал переименований (по умолчанию `rename_log.csv`) |
| `--force` | отключить проверки размера и OSHASH (осторожно) |
| `--suffix-collisions` | при занятой цели добавлять ` (2)`, ` (3)` вместо ошибки |

Применяются только строки с `approved` в значениях `y`, `yes`, `1`, `true`
(регистр не важен). Пустое значение и любой мусор означают `n` — такие строки
пропускаются, даже не доходя до проверки файловой системы.

Перед переименованием для каждой одобренной строки проверяется:

- `old` существует, это обычный файл (не symlink/junction);
- путь не выходит за пределы `--root` после нормализации;
- `new` — непустое относительное имя без подкаталогов, без недопустимых для
  Windows символов, не зарезервированное (`CON`, `PRN`, `AUX`, `NUL`,
  `COM1`–`COM9`, `LPT1`–`LPT9`), не длиннее 255 символов с расширением;
- расширение `new` совпадает с расширением `old`;
- размер и OSHASH файла совпадают с записанными в CSV (иначе `stale size` /
  `stale oshash`); `--force` отключает эту проверку;
- целевое имя свободно (иначе `target is occupied`); `--suffix-collisions`
  разрешает конфликт суффиксом.

Ручные правки в `new` **не санитизируются и не обрезаются молча**: строка с
недопустимым именем отклоняется с понятной ошибкой, чтобы итоговое имя всегда
совпадало с одобренным. Имена, предложенные самим `preview`, уже
санитизированы.

Переименование двухфазное: сначала файл переезжает во временное имя
`__ren_tmp_<uuid>` в той же папке, затем — в финальное. Это снимает проблему
цепочек `A → B, B → C` и проблему смены регистра. Если финальный `rename`
не удался, файлы откатываются на прежние места.

### Коды возврата

Одинаковы для обеих команд:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | были ошибки по отдельным файлам или временные сбои StashDB |
| `2` | фатальная ошибка: неверный ключ, ошибка запроса, битый CSV, нет такого каталога |

Ошибка ключа (401/403) у `preview` — фатальная: **CSV не пишется**, чтобы
неполный результат не выглядел как полноценный.

## Колонки CSV

`preview.csv` и `rename_log.csv` записываются в кодировке **UTF-8 с BOM**
(`utf-8-sig`) с разделителем **`;`** — так Excel открывает их без
дополнительных настроек. Дописываемый `rename_log.csv` BOM не переигрывает:
он есть только в заголовке нового файла.

Заголовок `preview.csv`:

```text
approved;old;new;source;confidence;scene_id;note;oshash;size
```

| Колонка | Содержимое |
|---|---|
| `approved` | `y` — переименовывать, `n` — не трогать. Принимаются также `yes`, `1`, `true`. |
| `old` | Текущее имя файла (путь относительно корня). |
| `new` | Предлагаемое имя. Это уже финальное имя: коллизии разрешены заранее. |
| `source` | Откуда взялось имя: `fingerprint`, `text`, `heuristic`, `unchanged`. |
| `confidence` | Уверенность: `1.00` — уникальный отпечаток, `0.99` — несколько отпечатков, score текстового совпадения `0…1`, `0.00` — эвристика. |
| `scene_id` | ID сцены StashDB; пусто, если сцена не найдена. |
| `note` | Пояснения: почему не нашлось, список кандидатов, `ambiguous`, `collision: (2)`, `stashdb_error`, `hash error: ...`. |
| `oshash` | 16 hex-символов — отпечаток файла на момент preview. |
| `size` | Размер файла в байтах на момент preview. |

Значения `source`:

- `fingerprint` — сцена найдена по OSHASH. Единственное совпадение с
  содержательным именем одобряется автоматически (`approved=y`); несколько
  совпадений — всегда `n`, все кандидаты перечислены в `note`.
- `text` — совпадение по текстовому поиску. **Никогда** не одобряется
  автоматически: нужен человек.
- `heuristic` — StashDB ничего не дал, имя собрано эвристикой.
- `unchanged` — имя уже корректное, переименование не требуется.

`rename_log.csv` записывается только при реальном переименовании и содержит
только фактически переименованные строки:

```text
timestamp;old;new;oshash;scene_id;source
```

`timestamp` — метка времени UTC в формате `YYYY-MM-DDTHH:MM:SSZ`; `new`
уже содержит фактическое имя (с суффиксом ` (2)`, если он был добавлен).

### Формулы Excel

Если `old` или `new` начинается с `=`, `+`, `-` или `@`, в CSV перед
значением ставится апостроф, чтобы Excel не выполнил это как формулу. При
чтении CSV один ведущий апостроф снимается. Если вы правите `new` вручную в
Excel, не вставляйте значения, начинающиеся с этих символов — Excel может
превратить их в формулу.

## Offline и refresh

- `--offline` — **сети нет вообще**: ни fingerprint-запросов, ни текстового
  поиска. Используется только локальный кэш; чего в кэше нет — уходит в
  эвристику. Кэш при этом не обновляется.
- `--refresh` — кэш игнорируется, StashDB опрашивается заново, кэш
  обновляется. `--refresh` и `--offline` вместе **несовместимы** (ошибка
  argparse, код 2).
- Если `STASHDB_API_KEY` не задан, `preview` сам переключается в офлайн-режим
  и печатает предупреждение — полноценный прогон без сети невозможен.
- `python -m video_renamer.scrapers.stashdb` без ключа, наоборот,
  завершается ошибкой (код 2).

Кэш лежит в `cache/title_fixer.sqlite3` (путь меняется флагом `--cache`) и
хранит **полный JSON сцены**, а не только идентификатор, — поэтому он
самодостаточен и с ним можно работать офлайн. TTL — 30 дней, причём
отрицательные результаты («сцены нет») тоже кэшируются: это защищает от
повторных запросов по заведомо бесполезным хешам.

```powershell
# прогон без сети по кэшу
python -m video_renamer.cli preview D:\Videos\PH --offline --csv preview.csv

# полностью свежий прогон по сети
python -m video_renamer.cli preview D:\Videos\PH --refresh --csv preview.csv
```

## Лимиты StashDB

Клиент ходит в `https://stashdb.org/graphql` заголовком `ApiKey` (это **не**
`Authorization: Bearer`).

| Ограничение | Значение |
|---|---|
| Отпечатки за один запрос | не более **40** сцен — клиент сам режет батчи |
| Текстовый поиск | `limit = 10` результатов на файл, один запрос на файл |
| Таймаут запроса | 30 с |
| Повторы | до 3 попыток |
| `429 Too Many Requests` | ждём `Retry-After` (целые секунды, не больше 300 с) |
| `5xx` и сетевые сбои | паузы 1 / 3 / 9 с |
| `401` / `403` и GraphQL `not authorized` | фатальная ошибка, без повторов |
| Пауза между запросами | 1 с |
| Студии | `queryStudios` пагинируется, `per_page` по умолчанию 100 |

Временная ошибка (сеть, 429 после всех попыток, упавший батч) **не роняет**
весь прогон: затронутые файлы получают `source=heuristic` и
`note=stashdb_error`, `approved=n`, остальные обрабатываются как обычно, а
команда завершается с кодом `1`, чтобы сбой не остался незамеченным.

Локальные ограничения:

- читаются только первые и последние 64 КиБ файла — полный файл не
  сканируется (на папке в десятки гигабайт это существенно);
- файлы в 8 байт и меньше пропускаются (OSHASH для них не считается);
- итоговое имя — не длиннее 255 символов с расширением;
- расширения видео: `.mp4`, `.mkv`, `.avi`, `.wmv`, `.mov`, `.m4v`,
  `.webm`, `.ts`, `.mpg`, `.mpeg`.

## Скрапер студий

```text
python -m video_renamer.scrapers.stashdb [--out data/studios.json] [--checkpoint data/studios_checkpoint.json]
                         [--raw data/studios_raw.json] [--per-page 100] [--delay 1.0]
                         [--max-pages N] [--apply] [--reset]
```

Без `--apply` команда — **dry-run**: она ходит в сеть и печатает статистику,
но не пишет ни одного файла.

С `--apply`:

- после **каждой** страницы сохраняются `data/studios_raw.json` и
  `data/studios_checkpoint.json` — обрыв сети не теряет уже собранное, повторный
  запуск продолжит с той же страницы;
- по завершении `data/studios.json` обновляется атомарно, предыдущая версия
  остаётся в `data/studios.json.bak`;
- ручные правки в `data/studios.json` не затираются: добавляются только новые
  ключи;
- коллизии нормализованных ключей (`Brazzers` и `Brazzers!`) пишутся в
  `data/studios_collisions.json` — первый по порядку API остаётся рабочим;
- `--reset` начинает с первой страницы (чекпоинт и raw при `--apply`
  удаляются);
- `--max-pages N` ограничивает число страниц — удобно для проверки;
- `--allow-empty-tail` принимает пустую последнюю страницу, если API
  сообщает `count` на несколько записей больше, чем реально отдаёт; без флага
  это считается разрывом пагинации;
- если в чекпоинте другой `--per-page`, скрапер требует `--reset`, чтобы не
  потерять прогресс.

Ключ нормализации тот же, что и в эвристике: имя в нижнем регистре без
пробелов, точек, подчёркиваний и дефисов.

Справочник используется только для распознавания студии в имени файла и в
эвристике; сам по себе он ничего не переименовывает.

### FansDB и ThePornDB

Ключи берутся из `.env`: `FANSDB_API_KEY` и `THE_PORNDB_API_KEY`.

```text
python -m video_renamer.scrapers.fansdb [--out data/studios_fansdb.json] [--apply] [--max-pages N]
python -m video_renamer.scrapers.theporndb [--seed data/studios.json] [--out data/studios_theporndb.json]
                                  [--apply] [--batch-size 50] [--max-batches N]
```

FansDB — обычный stash-box с `queryStudios`, поэтому его можно выгрузить
целиком. По умолчанию пишет `data/studios_fansdb.json`; чтобы добавить в основной
справочник, укажи `--out data/studios.json`.

ThePornDB **не поддерживает `queryStudios`**: в его схеме есть только
`findStudio` по имени/ID. Поэтому его скрапер не перечисляет всё, а обогащает
известные имена: берёт seed-файлы (по умолчанию `data/studios.json`), спрашивает
ThePornDB пакетами по 50 имён и добавляет канонические имена, родителей и
дочерние студии. Можно передать несколько seed-файлов:

```powershell
python -m video_renamer.scrapers.theporndb --apply --seed data/studios.json --out data/studios.json
python -m video_renamer.scrapers.theporndb --apply --seed data/studios.json --seed data/studios_fansdb.json
```

Полный прогон по `data/studios.json` — около 300 запросов. Если добавить в seed
`data/studios_fansdb.json` (почти 400 тысяч имён), это займёт несколько часов;
прогресс сохраняется после каждого пакета.

FansDB содержит очень много пользовательских студий (около 395 тысяч), поэтому
его полный прогон занимает около часа. Для проверки используй `--max-pages 1`,
для продолжения — обычный `--apply`.

По умолчанию включён фильтр мусорных имён: пустые, чисто числовые, слишком
короткие и явно сгенерированные ID вида `000000h (ManyVids)` или
`+AddFriends (network)` не попадают в итоговый JSON. Реальные названия вроде
`4based`, `XArt` и `SXT0229` остаются. На первых 500 студиях FansDB фильтр
отбросил 165 записей и оставил 335. Отключить фильтр можно флагом
`--no-filter` (например, если нужен полный сырой список).

### Слияние справочников

```powershell
python -m video_renamer.merge_studios data/studios.json data/studios_fansdb.json data/studios_theporndb.json --out data/studios.json --apply
```

Слияние аддитивное: первый встреченный вариант имени побеждает, существующие
записи не перезаписываются, а альтернативные написания попадают в
`data/studios_collisions.json`. Без `--apply` — dry-run.

## Возможные проблемы

### `error: StashDB rejected the request ... проверь STASHDB_API_KEY`

Это 401/403 или GraphQL-ответ `not authorized`.

- Ключ должен быть **API-ключом StashDB** со <https://stashdb.org>, а не
  паролем от аккаунта.
- Проверьте переменную в **той же** сессии терминала:
  `echo $env:STASHDB_API_KEY`. Если ключ пустой — задайте его заново.
- Лишние кавычки, пробелы и переносы строки внутри значения ломают
  авторизацию: `"ключ"` в переменной попадёт в заголовок вместе с кавычками.
- `setx` / `SetEnvironmentVariable` действует только в **новых** окнах
  терминала.
- Ключ не должен попадать в CSV, логи или коммиты — инструмент его туда не
  пишет.

`preview` при такой ошибке не пишет CSV и возвращает код 2.

### Совпадений нет: у всех строк `source=heuristic`

Так и должно быть для перекодированных «трубных» файлов: OSHASH совпадает
только с **точной копией** сцены, а перекодированный файл имеет другой
хеш. Что проверить:

- в `note` написана причина: `нет текстовых кандидатов`,
  `лучший score 0.52 < 0.60`, `текстовый guard не пройден`;
- не стоит ли `--no-text`: текстовый поиск — второй шанс найти сцену;
- свежесть `data/studios.json`: если студия не распознана, остаток имени
  получается мусорным. Обновите: `python -m video_renamer.scrapers.stashdb --apply`;
- качество исходного имени: чем больше в нём мусора, тем ниже score;
- кэш: после `--refresh` результаты пересчитываются, а не берутся из
  30-дневного кэша.

Текстовые совпадения (`source=text`) **всегда** требуют ручного одобрения:
порог score — 0.60, плюс дополнительный guard (совпадение по исполнителю или
близкое название). При сравнении названий имена актрис и студия вычитаются,
чтобы лишние слова в имени файла не занижали score. Отдельно учитываются
компактная дата (`260625` → `25.06.2026`) и `code` сцены. Если два подходящих
кандидата отличаются меньше чем на 0.05, в `note` будет `ambiguous`.
Уверенное текстовое совпадение помечается подробностями, например
`text: score=0.712, title_sim=0.820, performer_hit=0.50, studio_hit=1.0, date_hit=1.0, code_hit=0`.

### Excel: всё в одном столбце / файл открывается «кракозябрами»

Файл записан в UTF-8 **с BOM** и с разделителем `;`. Если Excel открыл его
неправильно:

- «Данные → Из текста/CSV» → разделитель `;` → кодировка UTF-8;
- не сохраняйте CSV обратно через «CSV (с запятыми)» — разделитель должен
  остаться `;`;
- не добавляйте и не переименовывайте колонки: `apply` проверяет наличие
  всех девяти и падает с `error: cannot read preview.csv: CSV is missing
  columns: ...`;
- не заливайте в `approved` ничего, кроме `y`/`yes`/`1`/`true`: всё
  остальное считается отказом.

### `error: ... stale size` / `stale oshash`

Файл изменился после `preview` (перезаписали, доаппарилили, сменили
размер). Самое правильное — перезапустить `preview` и заново проверить CSV.
`--force` снимает проверку, но переименование может лечь на уже другое
содержимое.

### `error: ... target is occupied`

Файл с таким именем уже существует. Варианты: убрать конфликтующую строку
из CSV, переименовать её вручную или добавить `--suffix-collisions` — тогда
цель станет `Имя (2).mp4`.

### `error: ... path escapes root` / `invalid new name`

Путь или имя в CSV нарушают ограничения (абсолютный путь, подкаталог,
зарезервированное имя Windows, длина > 255, недопустимые символы).
`preview` такие имена не генерирует — значит, строку правили руками.

### `preview` не находит файлы

Проверьте расширения (список выше), `--recursive` для подпапок и что путь
указывает на каталог, а не на файл: `error: not a directory: ...`, код 2.

## TUI

```powershell
scripts\start_tui.bat
# или сразу с папкой
scripts\start_tui.bat D:\Videos\PH
# напрямую, если .venv уже готов
.venv\Scripts\python.exe -m video_renamer.tui D:\Videos\PH
```

Что есть в первом TUI:

- выбор папки через дерево каталогов;
- статус ключа StashDB и размера `data/studios.json`;
- preview с прогресс-баром (в фоновом worker, без зависания экрана);
- таблица: новое имя, источник, confidence, комментарий;
- фильтры «Все / Не одобрено / Текст / Эвристика / Fingerprint / Без изменений»;
- `Space` или Enter — одобрить/снять строку, кнопки «Одобрить»/«Снять»;
- нижняя панель с полным старым именем, новым именем и заметкой;
- подтверждение apply в отдельной модалке и отчёт с `rename_log.csv`;
- горячие клавиши `p` (preview), `b` (папка), `space` (одобрить),
  `a` (apply), `q` (выход).

TUI зависит от Textual (`requirements/tui.txt`), но ядро остаётся на
стандартной библиотеке: CLI и тесты TUI-модели работают без Textual.

Пока TUI не запускает скраперы студий и не даёт выбирать альтернативных
кандидатов — это следующие итерации.

Вне объёма текущей версии также: PHASH и MD5 целого файла, GUI/веб-интерфейс,
запись метаданных в контейнер, интеграция с Jellyfin/Stash, переименование
подпапок и sidecar-файлов, автоудаление дублей.
