# Video Files Renamer

Переименовывает видеофайлы по данным **StashDB**, **FansDB** и **ThePornDB**:
студия, дата, исполнители и название — в одном понятном формате:

```text
Студия - ДД.ММ.ГГГГ - Исполнитель 1, Исполнитель 2 - Название.mp4
```

Работает локально на Windows. Сначала программа **только предлагает** новые
имена в таблице CSV, вы проверяете их в Excel и одобряете нужные строки, и
только после этого файлы переименовываются. Любое переименование можно
откатить.

> Наружу уходят только отпечатки файлов (OSHASH и PHASH) и поисковые запросы по
> очищенному имени. Видео целиком не отправляется и не загружается.

---

## Быстрый старт (Windows)

1. Установите Python 3.10 или новее и отметьте «Add python.exe to PATH».
2. Получите API-ключи (см. [Ключи](#ключи-api)) и положите их в файл `.env`
   в корне проекта (шаблон — `.env.example`).
3. Запустите **`scripts\start.bat`**, выберите папку с видео и пункт меню:
   - **1** — предложить новые имена (`preview.csv` откроется автоматически);
   - **2** — предложить имена и применить то, что вы одобрите;
   - **3** — применить уже проверенный `preview.csv`.
4. Для интерфейса с таблицей, фильтрами и кнопками запустите
   **`scripts\start_gui.bat`** (десктопный GUI на CustomTkinter) или
   **`scripts\start_tui.bat`** (текстовый TUI на Textual). Батники сами
   создадут окружение и поставят нужные зависимости.
5. `launcher.py` перед запуском GUI безопасно проверяет обновления Git:
   `git fetch`, затем `git pull --ff-only` только при чистом рабочем дереве.
   Сбой сети или локальные правки не мешают запуску.

Первый раз удобно попробовать на пяти файлах: в CLI это `--limit 5`.

## Что нужно

|---|---|---|
| Windows 10/11 | пути, длины имён и санитизация заточены под Windows | да |

| Textual | интерфейс TUI (`requirements/tui.txt`) | нет, нужен только для TUI |

Установка ffmpeg для PHASH: `winget install Gyan.FFmpeg`. Если программа не
находит `ffmpeg.exe`, укажите путь флагами `--ffmpeg` и `--ffprobe` или
переменными `FFMPEG_PATH` и `FFPROBE_PATH`.

## Ключи API

Ключи читаются из переменных окружения `STASHDB_API_KEY`, `FANSDB_API_KEY`,
`THE_PORNDB_API_KEY`. Если переменной нет, программа ищет файл `.env` в текущей
папке, затем в корне проекта. Значение из окружения важнее `.env`.

**Вариант 1 — файл `.env`** (проще всего):

```text
STASHDB_API_KEY=ваш-ключ
FANSDB_API_KEY=ваш-ключ
THE_PORNDB_API_KEY=ваш-ключ
```

**Вариант 2 — переменные в PowerShell** (только для текущего окна):

```powershell
$env:STASHDB_API_KEY = "ваш-ключ"
```

Файл `.env` не попадает в git. Ключи никогда не пишутся в CSV, журнал и вывод
программы.

## Как это работает

```text
  preview  ──►  preview.csv  ──►  проверка в Excel  ──►  apply --apply  ──►  rename_log.csv
 (ничего не       (approved=y,        (правка new,           (только y,          (журнал
  меняет)          new — финальное)    отказ от строк)        проверки файла)     откатов)
                                                                                   │
                                                              undo --ids  ◄────────┘
```

1. **preview** определяет сцену для каждого файла: сначала по отпечатку
   (OSHASH), затем по PHASH (если включён), затем по тексту имени, и только
   потом эвристикой. Результат — таблица `preview.csv`.
2. Вы проверяете таблицу: в колонке `approved` ставите `y` у нужных строк и при
   необходимости правите `new`.
3. **apply** переименовывает только строки с `y`, предварительно проверив, что
   файл не менялся с момента preview.
4. **undo** откатывает выбранные переименования по журналу.

## Команды

### `preview` — предложить имена

```powershell
python -m video_renamer.cli preview D:\Videos\PH --csv preview.csv
```

Файлы не меняются. Полезные флаги:

| Флаг | Что делает |
|---|---|
| `--limit N` | только первые N файлов (удобно для пробы) |
| `--recursive` | заходить в подпапки |
| `--offline` | без сети: только локальный кэш и эвристика |
| `--refresh` | игнорировать кэш и спросить базы заново |
| `--no-text` | не искать по тексту имени (быстрее, меньше совпадений) |
| `--phash` | искать ещё и по PHASH; медленно, нужен ffmpeg |
| `--no-secondary` | спрашивать только StashDB |

<details>
<summary>Все флаги <code>preview</code></summary>

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--csv PATH` | `preview.csv` | куда записать таблицу |
| `--recursive` | выкл. | обходить подпапки |
| `--limit N` | все файлы | обработать первые N |
| `--no-text` | выкл. | не делать текстовый поиск |
| `--offline` | выкл. | без сети |
| `--refresh` | выкл. | игнорировать кэш |
| `--studios PATH` | `data/studios.json` | справочник студий |
| `--cache PATH` | `cache/title_fixer.sqlite3` | файл кэша |
| `--phash` | выкл. | поиск по PHASH для файлов без совпадения по OSHASH |
| `--ffmpeg PATH` | `FFMPEG_PATH` или `PATH` | путь к ffmpeg |
| `--ffprobe PATH` | `FFPROBE_PATH` или `PATH` | путь к ffprobe |
| `--no-secondary` | выкл. | не опрашивать ThePornDB и FansDB |

Пути `--studios` и `--cache` привязаны к папке проекта, поэтому команду можно
запускать из любой папки.

</details>

### `apply` — переименовать

```powershell
python -m video_renamer.cli apply preview.csv --root D:\Videos\PH          # только план
python -m video_renamer.cli apply preview.csv --root D:\Videos\PH --apply  # переименовать
```

Без `--apply` команда ничего не меняет и печатает план. Переименовываются
только строки с `approved` = `y`, `yes`, `1` или `true`. Всё остальное —
отказ.

<details>
<summary>Все флаги <code>apply</code></summary>

| Флаг | Что делает |
|---|---|
| `--root PATH` | **обязательный**: папка, относительно которой заданы пути в CSV |
| `--apply` | реально переименовать (без флага — dry-run) |
| `--log PATH` | журнал (по умолчанию `rename_log.csv` в корне проекта) |
| `--force` | не проверять размер и OSHASH (опасно, см. ниже) |
| `--suffix-collisions` | при занятом имени добавлять ` (2)`, ` (3)` вместо ошибки |

</details>

### `undo` — откатить переименования

```powershell
python -m video_renamer.cli undo --list                      # активные строки журнала с id
python -m video_renamer.cli undo --ids 3fa9c2d1e0 --apply    # откатить (без --apply — проба)
```

- Журнал не переписывается и не теряет строк: откат записывается отдельной
  строкой `undo`.
- Перед откатом каждый файл проверяется: он на месте, его отпечаток совпадает
  с журналом, исходное имя свободно. Изменённый файл не откатывается.
- Строки, записанные до версии с откатом, не знают своей папки. Их можно
  откатить только с `--root` и `--confirm-legacy`.

### Интерфейс (TUI)

```powershell
scripts\start_tui.bat
scripts\start_tui.bat D:\Videos\PH
```

| Клавиша | Действие |
|---|---|
| `p` | preview выбранной папки |
| `b` | выбрать папку |
| `space` или Enter | одобрить или снять строку |
| `c` | выбрать другого кандидата (сцену) |
| `e` | вручную отредактировать имя |
| `s` | запустить скрапер студий или слияние справочников |
| `a` | применить одобренные строки (с подтверждением) |
| `u` | журнал переименований и откат выбранных |
| `q` | выход (спросит подтверждение, если таблица не пуста) |

Интерфейс рассчитан на окно 140×40; батник открывает консоль 150×45.

### Десктопный интерфейс (GUI)

```powershell
scripts\start_gui.bat
scripts\start_gui.bat D:\Videos\PH

# без батника: обновление Git + GUI
.venv\Scripts\python.exe launcher.py D:\Videos\PH

# напрямую, без проверки обновлений
.venv\Scripts\python.exe -m video_renamer.gui D:\Videos\PH
```

Слева — папка, Preview, статусы StashDB/FansDB/ThePornDB и статистика.
В таблице у каждой строки есть чекбокс одобрения, выпадающий список
кандидатов и редактируемое имя. «Применить» активно только при наличии
одобренных строк. Долгие операции (скан, хеширование, сеть, apply, скраперы)
идут в фоновых потоках; обновления возвращаются в Tk-поток через очередь.

Таблица виртуализирована: в памяти живёт только видимый пул строк, поэтому
сотни файлов не просаживают скролл. Горячие клавиши: `↑`/`↓` — выбор строки
с автоскроллом, `Space` — одобрить или снять выбранную строку,
`Ctrl+Enter` — применить, `F5` — Preview, `Esc` — снять выделение.
Пока идёт первый тяжёлый скан, показывается skeleton-заглушка и прогресс-бар.
Рядом с прогресс-баром во время Preview есть кнопка «Отмена»: она выставляет
`threading.Event`, и воркер останавливается на ближайшем checkpoint прогресса.

Отключить автообновление: `launcher.py --no-update` или
`set VIDEO_RENAMER_SKIP_UPDATE=1`.

## Что значат колонки CSV

Заголовок `preview.csv`:

```text
approved;old;new;source;confidence;scene_id;note;oshash;size
```

| Колонка | Содержимое |
|---|---|
| `approved` | `y` — переименовать, `n` — не трогать |
| `old` | текущее имя файла (относительно корня) |
| `new` | предложенное имя; коллизии уже разрешены |
| `source` | откуда имя: `fingerprint`, `phash`, `text`, `heuristic`, `unchanged` |
| `confidence` | уверенность: `1.00` — уникальный отпечаток, `0.90` — PHASH, `0…1` — текст |
| `scene_id` | ID сцены в базе; пусто, если сцена не найдена |
| `note` | пояснения: кандидаты, `ambiguous`, `stashdb_error`, `phash error: …` |
| `oshash`, `size` | отпечаток и размер на момент preview; по ним проверяется `apply` |

Значения `source`:

- **`fingerprint`** — сцена найдена по точному отпечатку. Единственное
  совпадение с нормальным именем одобряется автоматически. Если сцен несколько,
  одобрения нет, все варианты перечислены в `note`.
- **`phash`** — сцена найдена по перцептивному отпечатку (похожий, но не
  идентичный файл). **Всегда** требует вашего одобрения.
- **`text`** — совпадение по тексту имени. **Всегда** требует одобрения.
- **`heuristic`** — базы ничего не дали, имя собрано по правилам программы.
- **`unchanged`** — имя уже правильное.

**Excel.** Файлы пишутся в UTF-8 с BOM и разделителем `;`, так что открываются
сразу. Не сохраняйте их обратно как «CSV (с запятыми)» и не переименовывайте
колонки. Если значение в `old` или `new` начинается с `=`, `+`, `-` или `@`,
программа ставит перед ним апостроф, чтобы Excel не принял его за формулу.

## Безопасность

- `preview` ничего не переименовывает.
- `apply` без `--apply` только показывает план.
- Перед переименованием проверяется каждая строка: путь внутри папки, это
  обычный файл (не ярлык), размер и отпечаток совпадают с CSV, имя допустимо
  для Windows и не длиннее 255 символов, цель свободна.
- Переименование двухфазное: сначала во временное имя, потом в финальное.
  Цепочки `A → B, B → C` и смена регистра работают без конфликтов.
- Каждое выполненное переименование записывается в `rename_log.csv`; его можно
  откатить командой `undo`.
- `--force` отключает проверку размера и отпечатка. Используйте только если
  точно знаете, что файл тот же.

## Справочник студий

Программа распознаёт студию по справочнику `data/studios.json` (около
355 тысяч названий). Он уже лежит в репозитории. Обновить его можно скраперами:

```powershell
python -m video_renamer.scrapers.stashdb --apply
python -m video_renamer.scrapers.fansdb --apply
python -m video_renamer.scrapers.theporndb --apply
python -m video_renamer.scrapers.merge_studios data/studios.json data/studios_fansdb.json data/studios_theporndb.json --out data/studios.json --apply
```

Без `--apply` скрапер делает пробный запуск: ходит в сеть, но ничего не пишет.
С `--apply` он сохраняет прогресс после каждой страницы: обрыв не теряет
собранное, повторный запуск продолжает с того же места. Ручные правки в
`studios.json` сохраняются. Всё это же можно запустить из TUI (клавиша `s`).

<details>
<summary>Подробности по скраперам</summary>

- **StashDB и FansDB** перечисляют студии целиком через `queryStudios`.
- **ThePornDB** не умеет перечислять студии. Его скрапер проверяет имена из
  справочника через `findStudio` пакетами по 50 имён. Полный прогон по
  `data/studios.json` занимает около 300 запросов.
- **FansDB** содержит около 395 тысяч студий, полный прогон — около часа. Для
  проверки используйте `--max-pages 1`.
- Фильтр мусорных имён (пустые, числовые, сгенерированные ID вроде
  `000000h (ManyVids)`) включён по умолчанию; отключить — `--no-filter`.
- Если в чекпоинте другой `--per-page`, скрапер потребует `--reset`, чтобы не
  потерять прогресс.
- Лимиты API: до 40 отпечатков за запрос, таймаут 30 с, до 3 попыток; при
  `429` ждёт `Retry-After` (до 300 с), при сбоях сети и `5xx` паузы 1, 3 и 9 с.

</details>

## Справочник имён исполнителей

Локальная база имён помогает отделять актёров от названия, когда сцена не
нашлась или первое слово имени совпадает с названием студии. Источник — только
StashDB. Собрать справочник:

```powershell
python -m video_renamer.scrapers.performers --apply
```

Команда пишет `data/performers.json` (полная база, около 22 МБ) и
`data/performers_index.json` (индекс для поиска, около 4,3 МБ). Оба файла
генерируемые, не коммитятся и воспроизводятся за 2,5–3,5 минуты. Без
`--apply` — пробный запуск; прогресс сохраняется после каждой страницы.

В индекс попадают только многотокенные имена и алиасы, которые указывают
ровно на одного человека. Односложные (`Veronica`, `Zoe`) и неоднозначные
алиасы не используются: в имени файла они неотличимы от обычных слов.

Что меняется в preview:

- известные имена вырезаются **до** определения студии, поэтому
  `veronica-leal-...` не превращает `Veronica` в студию `VERONICA`;
- fallback собирает актёров из справочника, а не угадывает пары слов;
- в текстовый запрос попадают канонические имена, даже если они были вырезаны
  из остатка;
- строка всё равно не одобряется автоматически: справочник только улучшает
  кандидата и оставляет решение человеку.

Отключить справочник: `preview --no-names`; указать другой файл: `--names PATH`.
TUI подхватывает индекс автоматически, если он собран.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | были ошибки по отдельным файлам или временные сбои базы |
| `2` | фатальная ошибка: неверный ключ, битый CSV, нет папки |

Неверный ключ StashDB — фатальная ошибка: CSV в этом случае не пишется, чтобы
неполный результат не выглядел полноценным.

## Частые вопросы

**Все строки с `source=heuristic`.** Так бывает, если файл перекодирован: его
отпечаток отличается от базы. Попробуйте обновить справочник студий, убрать
`--no-text` или запустить `preview` с `--phash`. Причину смотрите в `note`.

**`error: StashDB rejected the request … проверь STASHDB_API_KEY`.** Ключ
неверный или пустой. Нужен API-ключ со stashdb.org, а не пароль от аккаунта.
Проверьте, что в значении нет лишних кавычек и пробелов.

**`error: … stale size` или `stale oshash`.** Файл изменился после preview.
Запустите preview заново и проверьте таблицу.

**`error: … target is occupied`.** Файл с таким именем уже есть. Уберите строку
из CSV или добавьте `--suffix-collisions`.

**Excel показывает всё в одном столбце.** «Данные → Из текста/CSV», разделитель
`;`, кодировка UTF-8.

**`preview` не находит файлы.** Проверьте расширения (`.mp4`, `.mkv`, `.avi`,
`.wmv`, `.mov`, `.m4v`, `.webm`, `.ts`, `.mpg`, `.mpeg`), флаг `--recursive` для
подпапок и что путь ведёт к папке.

**PHASH очень медленный.** Так и есть: на каждый файл запускается 25 кадров
ffmpeg, на обычной машине это несколько секунд на файл. Включайте `--phash` на
небольшой выборке или на файлах, которые не нашлись по отпечатку.

### Тесты

```powershell
python -m pip install -e ".[dev,tui,gui]"
python -m pytest -q
```

Тесты не ходят в сеть: клиент подменяется через `transport`, кэш и папки —
временные. Тесты TUI пропускаются, если Textual не установлен; тесты
GUI-виджетов — если недоступен Tk или нет дисплея.
