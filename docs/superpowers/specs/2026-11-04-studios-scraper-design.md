# Studios Scraper — короткий дизайн

- Замысел: разовый (перезапускаемый) скрипт тянет все студии из `https://stashdb.org/graphql` и пишет их в `studios.json` в формате чистильщика (`нормализованный_ключ -> ОтображаемоеИмя`), чтобы имена студий больше не вбивать руками.
- Цели: только официальные полные имена, без алиасов и доменов; ключ нормализуется тем же правилом, что в `clean_ph_names.py` (lower + снос пробелов/точек/дефисов/подчеркиваний); ключ API из `STASHDB_API_KEY`; пагинация до конца; ретраи + уважение к 429; докачка с чекпоинта; dry-run показывает, что будет записано, без записи.
- Не-цели: не тянем алиасы, URL, логотипы; никакой базы и картинок; скрипт отдельный, в прогон `clean_ph_names.py` не встраивается.
- Анти-цели: ключ нигде не хардкодится и не коммитится; API не долбим (пауза между страницами); обрыв не теряет прогресс; повторный прогон идемпотентен — тот же `studios.json`.
- Ограничения: заголовок `ApiKey`, не Bearer; точную форму поля `queryStudios` проверить живым запросом с ключом пользователя; Python + `httpx`; атомарная запись json; скрипт и чекпоинт лежат в `G:\Projects\Test_Projects`.
- Подходы: 1) stdlib-скрипт без зависимостей — просто, но прогон с начала при обрыве; 2) slim-порт их клиента на `httpx` с ретраями, 429 и докачкой — выбран, как единственный переживающий прогон на тысячи студий с возможностью перезапуска; 3) переиспользовать их бэкенд напрямую — отвергнут, тянет чужое репо с базой ради разовой задачи.
- Решили: вариант 2; только полные имена; ключ из окружения; скрипт остается в `Test_Projects`.
- На усмотрение строителя: точный GraphQL-запрос `queryStudios` по живой схеме; размер страницы; формат чекпоинта; CLI-флаги (`--dry-run`, `--max-pages`, `--reset`); что делать с дубликатами имен после нормализации.
